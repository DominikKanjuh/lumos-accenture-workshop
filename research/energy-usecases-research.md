# WattWise Energy – AI Use Case Research (Case 2)

Research date: 2026-11-25. Client assumption: German household electricity supplier, EUR, retail-heavy, owns billing + customer service + procurement and trading. It probably does not own a grid (in Germany, DSOs are unbundled), but it may own some renewable generation.

**Evidence grading:** **A** = company or regulator figure, or peer-reviewed. **B** = consultancy (McKinsey/BCG/IEA) benchmark. **C** = vendor case study or self-reported. **?** = no hard number found.

## 4. Feasibility considerations (cross-cutting)

| Dimension | Notes for WattWise |
|---|---|
| Data availability | **Strong:** billing line items, meter-read history, contract and CRM data, contact transcripts, tickets and git history, all owned and already contractual purpose. **Weak:** 15-min interval data (~5.5% of meters in DE), device data (needs OEM APIs), grid data (DSO-owned). |
| Maturity | Customer-service GenAI, coding assistants, anomaly detection and forecasting are mature (many production references). Flexibility/VPP and autonomous agents with write access are maturing. Grid AI is mature but not WattWise's domain. |
| Time to value | Agent assist, coding assistants and pre-bill anomaly detection in shadow mode: **6–12 weeks to pilot**. Churn model and load forecasting: 3–4 months. Autonomous agents and VPP: 6–18 months. |
| Regulatory risk | Low: billing QA, coding, agent assist. Medium: customer-facing chat (Art. 50 transparency, GDPR), personalised pricing, NILM (consent). High: credit scoring (Annex III), any grid control (Annex III critical infrastructure, from Dec 2027). NIS2 applies across all of these (logging, supplier risk). |
| Key risks | LLM hallucination in bills or advice (fix: grounded, templated generation plus numeric verification), wrong auto-corrections in billing (fix: human-in-the-loop until precision is proven), change management in the contact centre, vendor lock-in (Kraken, Salesforce, SAP), and dirty master data. |
| Dependencies | Billing system APIs, data platform (lakehouse), MLOps/LLMOps, AI governance board (AI Act inventory), works council (Betriebsrat) agreement for agent-performance tooling in Germany. |

## 5. Suggested evaluation framework (input for the team)
- **Value (0–5):** EUR impact (cost, revenue, leakage) + customer impact (CSAT, churn) + strategic fit (energy transition, regulatory mandate).
